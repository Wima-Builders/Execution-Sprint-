From launch traction to a repeatable Construction Procurement & Project Execution engine.

25 September 2026 → 23 December 2026 Executive Working Document Version 1.0

Purpose: convert Wima's current market presence, Deal Hub launch and Jamal Industries relationship into measurable demand, transactions, projects, trust assets and operating data.

1. Executive Mandate

The next 90 days are not primarily a technology project. They are a commercial proof-and-systemisation sprint. Wima should use technology only where it removes friction from a workflow that has already been proven manually.

02

03

Capture supplier, pricing, project, delivery and customer data while building a trusted network.

3. The 90-Day Flywheel

Marketing / Content → Qualified Enquiry → Deal Hub / Signature → RFQ → Quote Comparison → Procurement → Delivery / Installation → Project Record → Testimonial / Showcase → More Demand.

Every completed transaction should strengthen Wima's next transaction. Every project should create reusable evidence, content, supplier intelligence and customer trust.

4. Executive Priorities

Priority 1 — Revenue

  • Push Deal Hub demand.
  • Convert enquiries on WhatsApp.
  • Sell product bundles, not only individual products.

Priority 2 — Signature

  • Launch five productised transformation offers.
  • Acquire and execute 5 strong pilot projects.
  • Document before → procurement → execution → after.

Priority 3 — RFQ

  • Run RFQs manually first.
  • Compare price, availability, delivery and supplier performance.
  • Do not build software until 20–50 RFQs reveal the repeatable workflow.

Priority 4 — Trust

  • Verify a focused supplier network.
  • Create supplier/professional verification standards.
  • Publish evidence, not unsupported claims.

Priority 5 — Data

  • Capture every enquiry and quote.
  • Track supplier response and fulfilment.
  • Create a Wima Project Record for every project.

Priority 6 — Diaspora

  • Turn the Diaspora Procurement Desk into a defined service.
  • Use WhatsApp updates, documentation and milestones.
  • Sell control and visibility, not just sourcing.

13. Technology Rule

Do not build the tender platform first.
Run the workflow manually → identify repetition → standardise → measure → automate → then scale.

The first software requirement should come from observed bottlenecks in actual RFQs and projects, not from a feature wishlist.

16. Day-90 Board Review

At the end of the sprint, leadership should answer six questions with evidence:

  1. Which customer segments generate the strongest qualified demand?
  2. Which Deal Hub categories convert and produce acceptable economics?
  3. Which Signature packages sell and execute reliably?
  4. Which suppliers and professionals consistently perform?
  5. Which RFQ workflow steps should be automated?
  6. What must Wima deliberately not build yet?
Scale only the workflows that demonstrate demand, margin, reliability and repeatability.
